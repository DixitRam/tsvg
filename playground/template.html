Vector Video Format — VVF 0.1 draft

ORCH-78 · research, format spec, working reference player · 2026-11-23 · name .vvf is a placeholder (see decisions)
TL;DR
  • Nothing existing fits all of it. Closest is Lottie / dotLottie (vector, JSON, players on web/Android/iOS/Flutter, themes, experimental audio). It has no languages, no audio mixes, no layouts, no captions, no chapters, and its keyframe JSON is painful to hand- or AI-write.
  • Proposal: own format = one XML file (or a zip with assets) + a tiny side-effect-free expression language. A frame is a pure function f(time, options). No HTML, no JS inside.
  • Built and running below: reference web engine (canvas, ~400 lines core) with real video controls: timeline + chapters, scrub thumbnails, ±10 s, double-tap skip, speed, captions, pinch/scroll zoom that stays sharp, and viewer options for language, audio mix, theme, portrait/landscape.
  • Demo file: 40 s, 1 XML (~12 KB) → 2 layouts × 2 languages × 3 audio mixes × 2 themes = 24 variants. Edit the XML on the right; it re-plays instantly.
  • Next: your call on name, repo, phase-1 scope (Flutter engine? MP4 export? agent skill?). Questions on the ticket.

Does it already exist?

The format — VVF 0.1 (draft)

File

  • name.vvf — a zip: video.xml + assets/ (images, fonts, audio). Or plain name.vvf.xml when everything is vector/remote. Same document either way.
  • Time is continuous seconds. No frame rate in the file; the engine draws at the screen's rate (60/120 Hz). Size is in layout units, not pixels.

Document

<vvf version="0.1" title="@title">
  <layouts>   <layout id="landscape" w="1920" h="1080"/> <layout id="portrait" w="1080" h="1920"/>
  <options>   <option id="lang" label="Language" default="en"> <choice id="en"/> <choice id="gu" label="ગુજરાતી"/>
  <mixes>     <mix id="speech" voice="1" music="0" sfx="0"/>       ← gains per audio bus
  <themes>    <theme id="dark" bg="#0e1117" fg="#eef1f7" accent="#7aa2ff"/>   ← tokens: fill="$accent"
  <strings>   <s id="title" en="Vector Video" gu="વેક્ટર વિડિયો"/>            ← text="@title"
  <defs>      <fn id="wave" args="i,s">sin(t*s + i)</fn>   <symbol id="logo">…</symbol>
  <assets>    <asset id="pad" src="assets/pad.ogg"/>
  <music src="pad" loop="1"/>
  <backdrop> … nodes under every scene … </backdrop>
  <timeline>
    <scene id="intro" dur="7" chapter="@ch1">          ← scenes play in order; chapter = timeline mark
      <say at="0.6" text="@vo1" src.en="vo1_en"/>       ← narration: audio clip per language + caption text
      <sfx at="0.3" src="whoosh"/>
      <text x="=W/2" y="=H/2" y.portrait="=H/2-80" size="150" text="@title">
        <anim prop="opacity" from="0" to="1" dur="0.8"/>
        <keys prop="x" v="0:100; 1.2:300; 2:250" ease="io"/>
      </text>
    </scene>
  </timeline>
  <overlay> … nodes over every scene (logo, watermark) … </overlay>
</vvf>

Animation

  • <anim prop from to at dur ease/> — tween; from/to default to the base value. Colours tween too. Several anims on one prop chain in order.
  • <keys prop v="t:value; t:value"/> — keyframes.
  • Or just an expression on the attribute — any continuous motion (orbits, waves, counters).
  • Eases: linear in out io back elastic step.

Expression language (the "light script")

  • Numbers, 'strings', + - * / % ^, == != < > <= >=, && || !, c ? a : b, calls. No assignment, loops, I/O, DOM, clocks. Always terminates; same input → same output.
  • Variables: t (video time), T (scene time), p (scene progress 0–1), W H, portrait, layout, every option (lang mix theme …), $tokens.
  • Functions: sin cos tan abs sqrt min max floor ceil round pow exp log atan2 sign clamp lerp step smooth fract ease(k,'out') fmt str + your <fn>s.
  • Why so small: a parser + evaluator is ~120 lines in any language, so every native engine gets it exactly right. It is enough for every scene I could think of in tutorials and QA reels.

Audio, languages, captions

  • Buses: voice (<say>), music (<music>), sfx (<sfx>). A <mix> sets gains per bus; the viewer picks "Full", "Speech only", "No voice" — no re-encode.
  • <say> is the narration line: its text (string table, per language) is the caption; src.<lang> points at a pre-recorded clip. No clip for that language → the engine may speak it with on-device TTS, else captions only.
  • Pipeline idea: the author writes only text; a vvf bake tool calls a TTS (Kokoro for English, Sarvam/Google for Gujarati) and fills in src.* + exact durations. Change the script → re-bake only changed lines.
  • Chapters come from scene chapter=; they mark the timeline and label the scrub preview.

Native engines

Web builtCanvas 2D. vvf-core.js (parse, expressions, render) + vvf-player.js (controls, WebAudio mixer). Zero dependencies.
FlutterCustomPainter + Path/TextPainter; just_audio for buses. Same nodes, same expression evaluator in Dart.
Android / iOSCompose Canvas / SwiftUI Canvas (or one shared Rust core + Skia/ThorVG, like dotLottie does).
MP4 exportHeadless: render frames at 30/60 fps + mix audio → ffmpeg. For sharing on WhatsApp/YouTube; one export per chosen option set.
ConformanceGolden frames: (file, t, options) → PNG. Every engine must match within a tolerance. Determinism makes this trivial to test.
For agentsA skill: "write a .vvf instead of a video-like HTML page". The TaskManager thread could play .vvf attachments inline with this player.

Prototype limits (honest)

  • Gujarati voice is not baked — no Gujarati TTS on this Mac. Gujarati plays with Gujarati captions; voice only if the browser has a gu TTS voice. Phase 1 bake fixes it.
  • Audio pauses at speeds ≠ 1× (no pitch-corrected time-stretch yet).
  • Spec is a draft; no gradients, masks, filters, font embedding, zip loader yet.
  • Only the web engine exists; tested in Chrome (Playwright). Safari/Firefox not checked.
